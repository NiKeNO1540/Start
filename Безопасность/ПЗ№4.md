### 1. Схема конфигурации виртуальной сети

Для выполнения работы была развернута лабораторная среда в VirtualBox. Все виртуальные машины объединены в «Внутреннюю сеть» (Internal Network) для обеспечения связности и изоляции.

**Топология:**
1.  **RADIUS-сервер (Ubuntu Server):**
    *   IP-адрес: `192.168.1.10 / 24`
    *   ПО: FreeRADIUS
2.  **Сетевое устройство (Cisco Router / GNS3):**
    *   IP-адрес: `192.168.1.2 / 24`
    *   Роль: Клиент RADIUS (NAS - Network Access Server)
3.  **Рабочая станция администратора (Admin PC):**
    *   IP-адрес: `192.168.1.20 / 24`
    *   ПО: SSH-клиент (PuTTY)

### 2. Настройка RADIUS-сервера (Ubuntu + FreeRADIUS)

**1. Установка и запуск службы:**
```bash
sudo apt-get update
sudo apt-get install freeradius freeradius-utils -y
sudo systemctl start freeradius
sudo systemctl enable freeradius
```

**2. Настройка клиента (маршрутизатора):**
В файл конфигурации `/etc/freeradius/3.0/clients.conf` была добавлена запись для маршрутизатора:

```text
client router {
    ipaddr = 192.168.1.2
    secret = sharedsecret  # Секретный ключ для шифрования общения
    shortname = router
}
```

**3. Создание тестового пользователя:**
В файл `/etc/freeradius/3.0/users` добавлена учетная запись для централизованного входа:

```text
netadmin Cleartext-Password := "RadiusStrongPass"
```

После изменений служба была перезапущена: `sudo systemctl restart freeradius`.

---

### 3. Настройка сетевого оборудования (AAA)

На маршрутизаторе были выполнены команды для активации модели AAA и привязки к внешнему серверу.

**1. Создание локальных пользователей (Task 1):**
Созданы резервные учетные записи на случай недоступности сервера RADIUS.
```text
Router(config)# username admin privilege 15 secret Pa$$w0rd
Router(config)# username user privilege 1 secret UserPass
```

**2. Базовая настройка AAA и сервера RADIUS:**
```text
Router(config)# aaa new-model
Router(config)# radius-server host 192.168.1.10 auth-port 1812 acct-port 1813 key sharedsecret
```

**3. Настройка методов аутентификации и авторизации:**
Настроена проверка сначала через RADIUS, а при его недоступности — через локальную базу (`local`).
```text
Router(config)# aaa authentication login default group radius local
Router(config)# aaa authorization exec default group radius local 
```

**4. Настройка уровней доступа (Task 2):**
Включена авторизация команд конфигурации, чтобы сервер мог управлять правами на выполнение команд.
```text
Router(config)# aaa authorization config-commands
```

### 4. Результаты тестирования

Были проведены сценарии проверки работоспособности системы:

**Тест 1. Штатный режим (RADIUS доступен):**
*   **Действие:** Попытка подключения по SSH с рабочей станции (192.168.1.20) на маршрутизатор (192.168.1.2) с логином `netadmin` (пользователь с сервера).
*   **Результат:** Доступ предоставлен.
*   **Логи сервера:** В журнале FreeRADIUS (вывод команды `radtest` или `/var/log/freeradius/radius.log`) зафиксирована запись `Login OK`.

**Тест 2. Режим сбоя (RADIUS недоступен):**
*   **Действие:** Остановка службы FreeRADIUS (`sudo systemctl stop freeradius`) и попытка входа под пользователем `netadmin`.
*   **Результат:** Отказ в доступе (так как пользователя нет локально).
*   **Действие:** Вход под пользователем `admin` (локальный пользователь).
*   **Результат:** Доступ предоставлен (сработал метод `local` из списка `group radius local`).

### 5. Ответы на контрольные вопросы

**1. Какие компоненты включает система AAA?**
*   **Authentication (Аутентификация):** Кто вы? (Проверка логина/пароля).
*   **Authorization (Авторизация):** Что вам можно делать? (Назначение прав, привилегий, доступных команд).
*   **Accounting (Учет):** Что вы сделали? (Сбор статистики: время входа, введенные команды, объем трафика).

**2. В чем преимущества использования RADIUS перед локальной аутентификацией?**
*   **Масштабируемость:** Единая база пользователей для сотен устройств. При смене пароля сотрудника его нужно поменять только в одном месте.
*   **Безопасность:** Пароли не хранятся на каждом устройстве. При увольнении сотрудника доступ закрывается мгновенно ко всей сети.
*   **Логирование:** Централизованный сбор логов о входах (Accounting).

**3. Какие порты используются для работы RADIUS?**
Протокол работает поверх UDP.
*   **1812:** Аутентификация и авторизация.
*   **1813:** Учет (Accounting).
*(Старые версии использовали порты 1645 и 1646).*

**4. Как настроить резервный метод аутентификации?**
В команде настройки списка методов необходимо указать резервный метод после основного. Например:
`aaa authentication login default group radius local`
Здесь `local` сработает только в том случае, если сервер RADIUS не ответит (тайм-аут). Если сервер ответит «Access-Reject» (неверный пароль), переход к `local` не произойдет.

**5. Какие типы аутентификации поддерживает RADIUS?**
RADIUS поддерживает множество методов, включая:
*   PAP (Password Authentication Protocol) — передача пароля в открытом виде (требует шифрованного туннеля).
*   CHAP (Challenge Handshake Authentication Protocol) — более безопасный обмен хешами.
*   MS-CHAPv2 — протокол Microsoft.
*   EAP (Extensible Authentication Protocol) — для использования с сертификатами и смарт-картами (часто используется в Wi-Fi).

### 6. Выводы по работе

В ходе выполнения лабораторной работы была реализована схема централизованного управления доступом к сетевому оборудованию.
1.  Развертывание сервера FreeRADIUS в VirtualBox позволило эмулировать реальную корпоративную инфраструктуру.
2.  Настройка модели AAA на маршрутизаторе продемонстрировала гибкость управления безопасностью: возможность комбинировать удаленную (RADIUS) и локальную базы данных обеспечивает надежность доступа даже при сбоях сети.
3.  Использование общего секретного ключа (`sharedsecret`) является критическим элементом защиты трафика между маршрутизатором (NAS) и сервером аутентификации.

Система AAA значительно повышает уровень безопасности сети по сравнению с простым использованием локальных паролей.
