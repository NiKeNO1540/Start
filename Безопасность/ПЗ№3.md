### 1. Схема виртуальной сети

Для выполнения работы была развернута виртуальная лаборатория в среде VirtualBox. Сетевые адаптеры настроены в режим «Внутренняя сеть» (Internal Network) для обеспечения изоляции от внешней сети и хост-машины.

**Топология:**
*   **Узел 1 (Router):** Виртуальная машина с образом Cisco IOS (или эмулятор GNS3/Cisco Packet Tracer внутри ВМ).
    *   IP-адрес интерфейса: `10.0.0.1 / 24`
*   **Узел 2 (Admin PC):** Виртуальная машина (клиент с SSH, например, PuTTY).
    *   IP-адрес: `10.0.0.5 / 24`

### 2. Выполненные команды конфигурации

В ходе работы были выполнены следующие настройки на виртуальном маршрутизаторе для обеспечения безопасности удаленного доступа.

**А. Базовая настройка SSH и учетных записей:**
Настройка доменного имени и генерация ключей шифрования — обязательное условие для запуска SSH-сервера.

```text
Router> enable
Router# configure terminal
Router(config)# hostname LabRouter
LabRouter(config)# ip domain-name lab.local
LabRouter(config)# crypto key generate rsa
! (Выбрана длина ключа 1024 бит)
LabRouter(config)# username admin privilege 15 secret Pa$$w0rd123
LabRouter(config)# aaa new-model
LabRouter(config)# aaa authentication login default local
```

**Б. Настройка линий виртуального терминала (VTY) для SSH:**
Перевод линий VTY с небезопасного протокола Telnet на SSH.

```text
LabRouter(config)# line vty 0 4
LabRouter(config-line)# transport input ssh
LabRouter(config-line)# login authentication default
LabRouter(config-line)# exit
```

**В. Задание 1. Создание ACL для ограничения доступа:**
Создан список контроля доступа (ACL), разрешающий подключение только с IP-адреса администратора (`10.0.0.5`) и блокирующий всех остальных.

```text
LabRouter(config)# access-list 10 permit 10.0.0.5
LabRouter(config)# access-list 10 deny any
LabRouter(config)# line vty 0 4
LabRouter(config-line)# access-class 10 in
LabRouter(config-line)# exit
```

**Г. Задание 2. Настройка предупреждающего баннера:**
Установлен юридический баннер, уведомляющий о запрете несанкционированного доступа.

```text
LabRouter(config)# banner motd #
******************************************
WARNING: Unauthorized access is prohibited!
All activities are monitored.
******************************************
#
```

**Д. Защита консольного порта и сохранение конфигурации:**

```text
LabRouter(config)# line console 0
LabRouter(config-line)# password consolepass
LabRouter(config-line)# login
LabRouter(config-line)# end
LabRouter# copy running-config startup-config
```

### 4. Ответы на контрольные вопросы

**1. Какие преимущества дает использование VirtualBox для тестирования безопасности?**
*   **Изоляция:** Ошибки конфигурации или запуск вредоносного кода не влияют на реальную сеть и основную ОС.
*   **Снимки (Snapshots):** Возможность быстро откатить систему к исходному состоянию после неудачных экспериментов.
*   **Экономия:** Нет необходимости покупать физическое сетевое оборудование для обучения.

**2. Как настроить изоляцию виртуальной сети?**
В настройках виртуальной машины в разделе «Сеть» необходимо выбрать тип подключения **«Внутренняя сеть» (Internal Network)**. В этом режиме виртуальные машины видят только друг друга, но не имеют доступа к хост-машине и интернету, что создает идеальный «песочный» контур.

**3. Какие дополнительные меры безопасности можно применить в виртуальной среде?**
*   Настройка **Syslog** для отправки логов на удаленный сервер.
*   Настройка **NTP** для синхронизации времени (важно для логов).
*   Настройка **exec-timeout** для автоматического разлогинивания при простое.
*   Отключение неиспользуемых служб (CDP, HTTP server, BootP).
*   Настройка защиты от перебора паролей (login block-for).

**4. Как проверить эффективность настроенных правил доступа?**
*   Попытаться подключиться с разрешенных и запрещенных IP-адресов.
*   Использовать сканеры портов (Nmap) для проверки видимости сервисов.
*   Просмотреть счетчики срабатывания ACL на маршрутизаторе командой `show access-lists` (увеличение счетчика matches подтверждает работу правила).

### 5. Выводы по результатам работы

В ходе выполнения практической работы были освоены методы защиты сетевого оборудования в виртуальной среде.
1.  **Переход на SSH:** Доказана необходимость использования SSH вместо Telnet, так как SSH шифрует трафик, защищая пароли от перехвата.
2.  **Контроль доступа:** Применение ACL (Access Control Lists) на линиях VTY является критически важной мерой, позволяющей ограничить круг администраторов на сетевом уровне.
3.  **Идентификация:** Настройка локальной базы пользователей и AAA позволяет персонализировать доступ и отказаться от единого пароля на вход.
4.  **Юридическая защита:** Баннер MOTD служит важным предупреждением для злоумышленников и аудиторов безопасности.

Использование VirtualBox позволило безопасно отработать данные настройки без риска нарушения работы реальной сети.
