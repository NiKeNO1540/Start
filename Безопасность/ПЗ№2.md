### 2. Выполнение сканирования сети (Nmap)

С машины атакующего (Kali Linux) было проведено сканирование целевой машины для определения открытых портов и версий ПО.

**Использованные команды:**

1.  **Определение версий служб:**
    `nmap -sV 192.168.10.6`
    *Описание:* Сканирование с попыткой определить версию запущенного сервиса на открытых портах.

2.  **TCP-сканирование (полное соединение):**
    `nmap -sT 192.168.10.6`
    *Описание:* Осуществляет полное тройное рукопожатие (Three-way handshake). Этот метод наиболее надежен, но оставляет явные следы в логах сервера.

3.  **SYN-сканирование (стелс-режим):**
    `nmap -sS 192.168.10.6`
    *Описание:* Отправляет SYN-пакет, получает SYN-ACK, но не отправляет финальный ACK. Соединение не устанавливается до конца, что делает сканирование менее заметным для старых систем логирования.

**Результаты сканирования:**
В результате выполнения команд был обнаружен открытый порт **22/tcp**, служба **ssh**, версия **OpenSSH 8.2p1**.

### 3. Настройка средств защиты и моделирование атак

На целевой машине (Ubuntu) были установлены и настроены средства защиты.

**Установка ПО:**
```bash
sudo apt-get update
sudo apt-get install suricata fail2ban -y
```

#### Этап А: Проверка работы Suricata (IDS)
Suricata была запущена в режиме мониторинга интерфейса.
При повторном запуске сканирования `nmap -sS` с атакующей машины, в логах Suricata (`/var/log/suricata/fast.log`) были зафиксированы подозрительные пакеты.

**Результат:** Система обнаружила попытку сканирования сети, классифицировав её как потенциальную разведку (Information gathering).

#### Этап Б: Атака методом перебора (Brute-force) и реакция Fail2Ban

1.  **Подготовка атаки:**
    На Kali Linux созданы файлы словарей:
    *   `users.txt` (содержит логины: root, admin, user, test).
    *   `pass.txt` (содержит список популярных паролей).

2.  **Запуск атаки:**
    Использована утилита Hydra:
    `hydra -L users.txt -P pass.txt 192.168.10.6 ssh`

3.  **Работа защиты:**
    Служба Fail2Ban была настроена на мониторинг логов SSH (`/var/log/auth.log`). После 3-5 неудачных попыток входа с одного IP-адреса, Fail2Ban добавил правило в брандмауэр (iptables) для блокировки IP атакующего.

**Результат:**
Атака была успешно остановлена. Утилита Hydra выдала ошибку подключения (Connection refused/timed out).
Проверка статуса блокировки на целевой машине:
`sudo fail2ban-client status sshd`
*Вывод показал, что IP 192.168.10.5 находится в списке заблокированных (banned).*

### 4. Анализ защищенности и выводы

**Анализ:**
1.  Без активных средств защиты (Fail2Ban) служба SSH уязвима к атакам полного перебора. При достаточном времени злоумышленник может подобрать слабый пароль.
2.  Сканирование Nmap позволяет злоумышленнику точно узнать версии ПО, что помогает подобрать конкретные эксплойты под уязвимости версий.
3.  Использование IDS (Suricata) позволяет администратору увидеть факт разведки, но сама по себе IDS в режиме мониторинга не блокирует атаку, а только сигнализирует о ней.
4.  IPS/Блокировщики (Fail2Ban) эффективно предотвращают автоматизированный перебор паролей.

**Предложения по усилению защиты:**
1.  **Отключить вход по паролю:** Настроить аутентификацию только по SSH-ключам.
2.  **Сменить стандартный порт:** Перенести SSH с 22 порта на нестандартный (например, 2222), чтобы избежать автоматических сканеров ботнетов.
3.  **Запрет root-доступа:** Запретить вход пользователю `root` по SSH в конфигурации `/etc/ssh/sshd_config`.
4.  **Настройка Firewall:** Использовать `ufw` или `iptables` для разрешения доступа только с доверенных IP-адресов (белый список).

### 5. Ответы на контрольные вопросы

**1. Какие типы сетевых атак существуют?**
К основным типам относятся:
*   **Reconnaissance (Разведка):** Сканирование портов, анализ версий ОС (например, Nmap).
*   **Brute-force (Полный перебор):** Подбор паролей к учетным записям.
*   **DoS/DDoS (Отказ в обслуживании):** Перегрузка ресурсов системы для вывода её из строя.
*   **Man-in-the-Middle (MITM):** Перехват и анализ трафика между узлами (сниффинг).
*   **Эксплойтинг:** Использование уязвимостей в ПО для внедрения вредоносного кода.

**2. Для чего используется Nmap?**
Nmap (Network Mapper) — это утилита для исследования сети и аудита безопасности. Она используется для обнаружения активных хостов в сети, открытых портов, запущенных служб (и их версий), а также определения типа операционной системы удаленного узла.

**3. Как работает система обнаружения вторжений (IDS)?**
IDS (например, Suricata или Snort) анализирует копию сетевого трафика в реальном времени. Она сравнивает пакеты с базой сигнатур (признаков известных атак) или анализирует аномалии в поведении. При совпадении IDS генерирует предупреждение (аллерт) в лог-файл для администратора.

**4. Принцип действия Fail2Ban?**
Fail2Ban сканирует лог-файлы сервисов (например, `/var/log/auth.log` для SSH) на предмет ошибок аутентификации. Если с определенного IP-адреса фиксируется заданное количество неудачных попыток входа за короткий промежуток времени, Fail2Ban автоматически обновляет правила брандмауэра (iptables/nftables), блокируя этот IP-адрес на заданное время.

**5. Какие меры защиты можно применить против брутфорс-атак?**
*   Ограничение количества попыток входа (Fail2Ban).
*   Использование сложных, длинных паролей.
*   Использование многофакторной аутентификации (2FA).
*   Использование CAPTCHA на веб-формах входа.
*   Полный отказ от паролей в пользу ключевой аутентификации (SSH keys, сертификаты).
