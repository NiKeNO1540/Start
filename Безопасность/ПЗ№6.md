### 1. Цель работы
Освоение практических навыков установки, настройки и конфигурирования системы предотвращения вторжений (IPS) Suricata в виртуальной среде VirtualBox. Изучение синтаксиса сигнатур и правил для обнаружения и блокировки вредоносного сетевого трафика.

### 2. Схема виртуальной сети и оборудование
Для выполнения работы была развернута лабораторная среда в VirtualBox, состоящая из двух виртуальных машин, объединенных в изолированную сеть («Внутренняя сеть» / Internal Network).

*   **Узел 1 (IPS Server / Target):**
    *   ОС: Ubuntu Server 20.04 / 22.04
    *   IP-адрес: `192.168.10.10`
    *   ПО: Suricata (IDS/IPS)
*   **Узел 2 (Attacker / Client):**
    *   ОС: Kali Linux / Ubuntu Desktop
    *   IP-адрес: `192.168.10.20`
    *   Роль: Генерация легитимного и вредоносного трафика (ping flood, HTTP scan).

### 3. Выполнение практических заданий

#### Задание 1. Настройка базового функционала

**1. Установка и запуск Suricata**
На сервере были выполнены команды для обновления репозиториев и установки пакета:
```bash
sudo apt-get update
sudo apt-get install suricata -y
```
После установки служба была добавлена в автозагрузку и запущена:
```bash
sudo systemctl enable suricata
sudo systemctl start suricata
```

**2. Настройка интерфейсов и сети**
Для определения имени сетевого интерфейса использовалась команда `ip a`. В моем случае интерфейс имеет имя `enp0s3`.

Редактирование конфигурационного файла:
`sudo nano /etc/suricata/suricata.yaml`

Внесенные изменения:
*   В секции `vars` -> `address-groups` указана защищаемая подсеть:
    `HOME_NET: "[192.168.10.0/24]"`
*   В секции `af-packet` настроен интерфейс прослушивания:
    ```yaml
    af-packet:
      - interface: enp0s3
        cluster-id: 99
        cluster-type: cluster_flow
        defrag: yes
    ```

**3. Обновление сигнатур**
Для загрузки базы правил Emerging Threats Open использовалась утилита:
```bash
sudo suricata-update
```
Это позволило получить актуальные базы известных атак.

#### Задание 2. Создание политик безопасности

Были созданы пользовательские правила в файле `/etc/suricata/rules/local.rules`. Перед этим убедились, что путь к этому файлу прописан в `suricata.yaml` в разделе `rule-files`.

**1. Правило обнаружения ICMP-флуда**
Задача: Обнаружить отправку большого количества ICMP-пакетов (ping) за короткое время.
```text
alert icmp any any -> $HOME_NET any (msg:"ICMP Flood Detected"; threshold: type limit, track by_src, count 5, seconds 20; sid:100001; rev:1;)
```
*Пояснение:* Правило создает оповещение (alert), если с одного IP придет более 5 пакетов ICMP за 20 секунд.

**2. Правило для подозрительного HTTP-трафика**
Задача: Реагировать на попытки сканирования веб-сервера.
```text
alert http any any -> $HOME_NET 80 (msg:"Suspicious HTTP Request - GET"; content:"GET"; http_method; threshold: type limit, track by_src, count 10, seconds 60; classtype:web-application-attack; sid:100002; rev:1;)
```

**3. Правило блокировки (режим IPS)**
Для демонстрации блокировки было написано правило `drop`.
*(Примечание: Для работы drop Suricata должна быть запущена в режиме inline, например, через NFQUEUE).*
```text
drop icmp any any -> $HOME_NET any (msg:"DROP ICMP Traffic"; sid:100003; rev:1;)
```

После добавления правил конфигурация была перезагружена:
`sudo systemctl restart suricata`

### 5. Ответы на контрольные вопросы

1.  **Какие типы атак может обнаруживать IPS?**
    IPS может обнаруживать DoS/DDoS атаки, сканирование портов, попытки эксплуатации уязвимостей (эксплойты), атаки на веб-приложения (SQLi, XSS), распространение вредоносного ПО, аномалии протоколов и политик доступа.

2.  **В чем отличие активной и пассивной защиты?**
    *   **Пассивная (IDS):** Только обнаруживает угрозу, записывает в лог и уведомляет администратора (Alert), но не вмешивается в трафик.
    *   **Активная (IPS):** Обнаруживает угрозу и автоматически предпринимает действия по её блокировке (Drop, Reject), разрывая соединение.

3.  **Как происходит обновление сигнатур?**
    Обновление происходит путем скачивания свежих баз правил (rulesets) из внешних репозиториев (например, Emerging Threats) с помощью утилиты `suricata-update` или `pulledpork`. После скачивания необходимо перезагрузить правила в движке.

4.  **Какие действия можно настроить при обнаружении атаки?**
    *   **Alert:** Записать в журнал.
    *   **Drop:** Отбросить пакет и заблокировать передачу (только в IPS режиме).
    *   **Reject:** Отбросить пакет и отправить отправителю TCP RST или ICMP Unreachable.
    *   **Pass:** Пропустить пакет (игнорировать остальные правила).
    *   **Log:** Только записать пакет (для анализа).

5.  **Как проверить работоспособность IPS?**
    *   Использовать инструменты генерации трафика (ping, hping3, curl).
    *   Запустить тестовую утилиту replay (tcpreplay) с pcap-файлами известных атак.
    *   Использовать стандартное правило для проверки: `alert ip any any -> any any (msg:"GPL ATTACK_RESPONSE id check returned root"; content:"uid=0(root)"; clsasstype:bad-unknown; sid:2100498; rev:7;)`.
    *   Проверить наличие записей в файлах `/var/log/suricata/fast.log` или `eve.json`.
